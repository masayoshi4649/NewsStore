# MCP 記事参照機能

## 目的

NewsStore に保存された記事を MCP クライアントから参照できるようにする。
MCP は既存の HTTP サーバーへ同居させ、管理画面と同じ待受ポートの `/mcp` で提供する。
最上位の `http.ServeMux` が `/mcp` を MCP へ、それ以外を既存の Gin 管理画面へ振り分ける。
記事や取得対象の作成、変更、削除、取得実行は公開せず、参照だけに限定する。

閉域ネットワークでの利用を前提とするため、アプリケーション内の認証は設けない。
インターネットへ直接公開せず、ファイアウォール、VPN、接続元制限などで到達可能な端末を管理する。

## 通信方式

- エンドポイントは `POST /mcp` とする。
- MCP の Streamable HTTP をステートレスな JSON 応答だけで使用する。
- 記事参照 tool は MCP プロトコル版 `2025-11-25` と互換にする。
- セッション、SSE、MCP のログ配信機能は使用しない。
- resources と prompts は公開しない。
- tools は `list_sources`、`search_articles`、`get_article` の 3 個だけを公開する。
- 初期化応答の `instructions` は設定せず、各 tool の説明は機能と入出力だけを記載する。
- リクエストの `Content-Type` は `application/json` を必須とする。
- リクエスト本文は 1 MiB を上限とする。
- `Origin` ヘッダーは検証せず、付与の有無や値にかかわらず受け付ける。
- `GET`、`PUT`、`PATCH`、`DELETE` など `POST` 以外のメソッドは拒否する。
- 1 回の PostgreSQL 問い合わせは最大 60 秒で中止し、停止した DB が接続と処理枠を占有し続けることを防ぐ。
- HTTP 応答期限は 75 秒とし、DB 問い合わせ完了後の応答処理時間を確保する。

ステートレス動作により、クライアントごとのセッション情報やイベント再送用データをアプリケーションメモリーへ保持しない。
応答を JSON に限定し、SSE 接続の維持とイベント管理に伴う処理を省く。

## MCP 設定

無条件検索時の既定記事件数は `conf/mcp.toml` に保存する。
`conf/system.toml` は `[SYSTEM] Port` だけを保持し、MCP 設定を混在させない。

```toml
[MCP]
DefaultArticleLimit = 20
```

`DefaultArticleLimit` の既定値は 20、指定可能範囲は 1 以上 100 以下とする。
`search_articles` で `limit` を省略した場合は、検索条件の有無にかかわらずこの値を使用する。

## `list_sources`

検索条件へ指定する取得対象 ID と設定名を一覧取得する読み取り専用 tool とする。
入力項目は持たない。

論理削除されていない `news_sources` を返す。
無効な取得対象も保存済み記事の検索に利用できるため、`enabled = false` の行を除外しない。
管理画面で保存した表示順で返し、同じ表示順の場合は `id` の昇順で安定させる。

出力の `sources` は次の項目を持つ。

- `id`: `news_sources.id`
- `name`: 管理画面で設定した取得対象名
- `kind`: `rss`、`reuters`、`fisco` のいずれか
- `enabled`: 現在の有効状態

## `search_articles`

保存済み記事を新しい順に検索する読み取り専用 tool とする。

### 入力

| 項目 | 型 | 必須 | 制約 |
| --- | --- | --- | --- |
| `query` | 文字列 | いいえ | 後方互換用の検索語。空白除去後の空文字は条件なし |
| `keywords` | 文字列配列 | いいえ | 追加の検索語。`query` と合わせて最大 5 個 |
| `source_id` | 整数 | いいえ | 取得対象 ID。未指定時は全取得対象 |
| `date_from` | RFC3339 文字列 | いいえ | 単独指定時の検索日時の下限。この日時と同じ記事を含む |
| `date_to` | RFC3339 文字列 | いいえ | 単独指定時の検索日時の上限。この日時と同じ記事を含む |
| `limit` | 整数 | いいえ | 1 以上 100 以下。省略時は `DefaultArticleLimit` |
| `cursor` | 文字列 | いいえ | 前ページの `next_cursor`。最初の検索では省略 |

### 検索方法

すべての入力条件は任意とし、取得対象、日時範囲、検索語をすべて同時に指定できる。
条件間は AND とする。
条件を何も指定しない場合は、全取得対象の記事から `DefaultArticleLimit` 件を新しい順に返す。

`query` と `keywords` は各値の前後の空白を除去し、重複を排除してから合計個数を判定する。
正規化後の検索語は最大 5 個とし、各語の条件を AND で結合する。
1 つの検索語は見出しまたは本文のどちらかに部分一致すれば、その語に一致したものとする。
検索語内の `%`、`_`、`\` はワイルドカードやエスケープ指定ではなく通常文字として扱う。
1～2 文字の検索語も指定できるが、`pg_trgm` が有効な trigram を作れないため、
記事数が多い環境では `source_id` や日時範囲との併用、または 3 文字以上の検索語を推奨する。

記事の検索日時と並べ替え日時には `COALESCE(published_at, fetched_at)` を使用する。
公開日時がある記事は公開日時、ない記事は取得日時で判定し、日時の降順、同日時では記事 ID の降順に並べる。
`date_from` と `date_to` の両方を指定した場合は入力順を問わず、早い日時を下限、遅い日時を上限へ自動的に正規化し、両端を検索対象に含める。
片方だけを指定した場合は、`date_from` を下限、`date_to` を上限として扱う。
条件一致数が `limit` を超える場合は、この並びで新しい記事を優先する。

日時と記事 ID を組み合わせた不透明な `cursor` による keyset pagination を使用する。
`cursor` 指定時は、前ページ末尾より古い日時、または同日時で小さい記事 ID を検索する。
`OFFSET` と全件数を求める `COUNT` は使用しない。
要求件数より 1 件だけ多く取得し、その 1 件の有無から `has_more` を決定する。

返却する見出しと記事本文は先頭 500 文字とし、SQL で必要な範囲だけを読み出す。
取得対象名、取得元識別子、URLなどの文字列にも返却上限を設け、異常に大きい保存値で応答が肥大化しないようにする。
検索結果には raw payload を含めない。

### 出力

- `articles`: 記事 ID、取得対象、外部 ID、リビジョン ID、URL、見出し、本文抜粋、公開日時、更新日時、取得日時、検索・並べ替えに用いた日時
- `has_more`: 続きが存在する場合は `true`
- `next_cursor`: 続きが存在する場合に、次の呼び出しへそのまま渡す不透明な文字列

`has_more` が `false` の場合、`next_cursor` は返さない。
検索条件を維持したまま `next_cursor` を次の `cursor` に指定する。

検索条件にはカーソル自体の有効期限を設けない。
ただし、カーソル生成後に記事を削除するなど DB の状態が変わった場合は、同じ結果集合を保証しない。

現時点では、OR 条件、関連度や類似度による並べ替え、同じ外部記事の最新リビジョンだけへの集約、日本語形態素解析による単語検索は提供しない。

## `get_article`

記事 ID を指定し、記事情報と本文の一部を取得する読み取り専用 tool とする。
長い本文を 1 回の応答へ載せず、文字位置による分割取得を行う。

### 入力

| 項目 | 型 | 必須 | 制約 |
| --- | --- | --- | --- |
| `id` | 整数 | はい | 1 以上の記事 ID |
| `body_offset` | 整数 | いいえ | 本文の開始文字位置。既定値 0、最大 10,000,000 |
| `body_limit` | 整数 | いいえ | 取得文字数。既定値 8,000、最大 16,000 |

### 本文取得方法

PostgreSQL の `SUBSTRING` で `body_offset` から `body_limit + 1` 文字だけを読み出す。
余分な 1 文字の有無から `has_more` を決定し、クライアントへは最大 `body_limit` 文字を返す。
アプリケーションへ本文全体を読み込んでから切り出す処理は行わない。

`body_offset` と `body_limit` はバイト位置ではなく文字位置として扱う。
続きがある場合の `next_body_offset` は、現在の `body_offset` に実際に返した文字数を加えた値とする。

### 出力

- 記事 ID、取得対象、外部 ID、リビジョン ID、URL、見出し、公開日時、更新日時、取得日時
- `body_text`: 指定範囲の本文
- `body_offset`: 今回の本文開始文字位置
- `has_more`: 本文の続きが存在する場合は `true`
- `next_body_offset`: 続きが存在する場合に次の呼び出しへ渡す開始文字位置

`has_more` が `false` の場合、`next_body_offset` は返さない。

## エラーと公開情報

- 入力値の範囲外は tool の入力エラーとして返す。
- 存在しない記事 ID は、記事が見つからないことだけを返す。
- PostgreSQL の接続情報、SQL、内部エラー詳細はクライアントへ返さない。
- `news_articles.raw_payload` は検索と詳細取得のどちらにも含めない。
- 内部エラーの詳細はサーバー側で記録し、MCP 応答は一般化したメッセージにする。

## 軽量化方針

1. MCP を別プロセスにせず、既存の HTTP サーバーと DB コネクションプールを共有する。
2. ステートレス JSON 応答だけを使い、セッションと SSE を管理しない。
3. 公開機能を 3 個の読み取り専用 tool に限定し、resources、prompts、MCP のログ配信機能を登録しない。
4. 検索は日時と記事 ID の keyset pagination と `limit + 1` 件取得を使い、`COUNT` と `OFFSET` を避ける。
5. 検索結果の上限を 100 件、本文抜粋を 500 文字に固定する。
6. 詳細本文は SQL で最大 16,001 文字だけ読み、最大 16,000 文字ずつ返す。
7. tool の出力専用構造体を使用し、不要な DB 列と raw payload を公開しない。
8. `COALESCE(published_at, fetched_at)` と記事 ID の検索順に合わせた式インデックスを使用する。

部分一致検索では 3 文字以上の検索語を `pg_trgm` の GIN インデックスで絞り込める。
1～2 文字だけの検索は索引の効果が限定されるため、取得対象または日時範囲を併用して走査対象を狭める。

## SDK と Go バージョン

通常の `go run .` を既存の Go 1.24.2 で維持するため、公式 MCP Go SDK は `v1.3.1` に固定する。
同 SDK が利用する JSON 実装は、Unicode NUL を含むキー処理が修正された `github.com/segmentio/encoding v0.5.4` を明示的に選択する。

SDK の当該版だけでは Streamable HTTP の Content-Type を検証しないため、MCP ハンドラーの前段で次を独自に強制する。

- `Content-Type: application/json` 以外を拒否する
- 圧縮要求を拒否する
- 本文を 1 MiB までに制限する
- `POST` 以外を拒否する

この境界処理は SDK の更新後も二重防御として維持する。
`Origin` ヘッダーは境界処理の判定に使用せず、要求をそのまま MCP ハンドラーへ渡す。

## クライアント設定

MCP クライアントには次の URL を Streamable HTTP エンドポイントとして設定する。

```text
http://localhost:8080/mcp
```

別端末から接続する場合は `localhost` を NewsStore 稼働端末の IP アドレスへ置き換える。
`Origin` ヘッダー付きのクライアントからも接続できる。
